## 1. Canonical Schema Decision

The canonical schema for the AI Website Agent persistence layer is defined in:
`backend/storage/sqlite_storage.py` (`SQLiteStorage`)

### Why `sqlite_storage.py` is Canonical
1. **Contract Alignment**: Implements `StoragePort` (`backend/api/services/ports.py`), which is the integration contract required by `backend/api`, `backend/agent`, and Sprint 2/3 integration specifications (`docs/module-ownership.md`, `docs/sprint3-contracts.md`).
2. **Type & Route Consistency**: Uses integer auto-increment primary keys (`INTEGER PRIMARY KEY AUTOINCREMENT`), directly matching REST API route path and query parameters (`/api/projects/{project_id:int}`, `/api/tasks?project_id=...`, `/api/preview/{project_id:int}/`).
3. **Session & Execution Richness**: Includes the `sessions` table and structured `executions` table (with `command`, `status`, `stdout`, `stderr`, `retry_count`, `duration_ms`, `reason`, and `created_at`), which are required for task execution history, approval flows, and audit logs.
4. **Versioned Migrations**: Uses `PRAGMA user_version` and an ordered `MIGRATIONS` list to safely evolve the database schema across releases without data loss or race conditions.
5. **Durable Idempotency & File Metadata**: Extends the schema with `idempotency_keys` and `file_metadata` tables, ensuring replay protection and generated site asset tracking survive process restarts.

## 2. Canonical Table Definitions

### `projects`
Stores high-level website generation projects.
```sql
CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```

### `sessions`
Tracks interactive sessions associated with a project.
```sql
CREATE TABLE sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    started_at TEXT NOT NULL
);
CREATE INDEX idx_sessions_project ON sessions(project_id);
```

### `tasks`
Ordered plan steps generated by the agent and orchestrated by the runner.
```sql
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    type TEXT NOT NULL,
    prompt TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending'
);
CREATE INDEX idx_tasks_project ON tasks(project_id);
```

### `executions`
Detailed execution records of actions performed for a task.
```sql
CREATE TABLE executions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    command TEXT NOT NULL,
    status TEXT NOT NULL,
    stdout TEXT NOT NULL DEFAULT '',
    stderr TEXT NOT NULL DEFAULT '',
    retry_count INTEGER NOT NULL DEFAULT 0,
    duration_ms INTEGER NOT NULL DEFAULT 0,
    reason TEXT,
    created_at TEXT NOT NULL
);
CREATE INDEX idx_executions_task ON executions(task_id);
```

### `idempotency_keys`
Durable idempotency store ensuring API retries replay cached responses without re-running work.
```sql
CREATE TABLE idempotency_keys (
    owner TEXT NOT NULL,
    scope TEXT NOT NULL,
    key TEXT NOT NULL,
    fingerprint TEXT NOT NULL,
    status_code INTEGER,
    response_json TEXT,
    created_at REAL NOT NULL,
    PRIMARY KEY (owner, scope, key)
);
CREATE INDEX idx_idempotency_created ON idempotency_keys(created_at);
```

### `file_metadata`
Tracks files created in project workspaces, providing auditability and isolation verification.
```sql
CREATE TABLE file_metadata (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    path TEXT NOT NULL,
    size_bytes INTEGER NOT NULL,
    sha256 TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (project_id, path)
);
CREATE INDEX idx_file_metadata_project ON file_metadata(project_id);
```

## 3. Legacy `database.py` Comparison and Usage Report

### Comparison Summary
| Attribute | Legacy `database.py` (Sprint 1) | Canonical `sqlite_storage.py` (Sprint 2 & 3) |
| :--- | :--- | :--- |
| **Primary Keys** | `TEXT PRIMARY KEY` (UUID strings) | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| **Sessions** | Does not exist | `sessions` table with foreign key to `projects` |
| **Tasks Columns** | `(id, project_id, description, status, created_at)` | `(id, project_id, type, prompt, status)` |
| **Executions Columns**| `(id, task_id NULLABLE, success INTEGER, stdout, stderr, duration_ms, retry_count, created_at)` | `(id, task_id NOT NULL, command, status, stdout, stderr, retry_count, duration_ms, reason, created_at)` |
| **Connection Scope** | Module-level global connection helper | Per-instance `_connect()` context manager with 30s timeout |
| **Foreign Keys** | `PRAGMA foreign_keys = ON;` in scripts | `PRAGMA foreign_keys = ON` enforced on every connection |
| **Migration Tracking**| None (`CREATE TABLE IF NOT EXISTS`) | Versioned migrations tracked via `PRAGMA user_version` |

### Legacy Code Usage Report
Before deprecating or removing `backend/storage/database.py`, its active references across the codebase were cataloged:
1. `backend/storage/__init__.py`: imports `DEFAULT_DB_PATH`, `configure_database`, `connection_scope`, `get_connection`, `init_db`, `resolve_db_path`.
2. `backend/storage/repositories/projects.py`: imports `connection_scope`, `init_db`.
3. `backend/storage/repositories/tasks.py`: imports `connection_scope`, `init_db`.
4. `backend/storage/repositories/executions.py`: imports `connection_scope`, `init_db`.
5. `tests/unit/test_storage.py`: exercises the Sprint 1 repository helpers through `backend.storage`.

### Reconciliation Strategy
- The public `backend.storage` package now exposes `SQLiteStorage` as the primary storage implementation.
- `SQLiteStorage` includes automated migration support for legacy Sprint 1 databases (`user_version == 0` with legacy tables) to safely upgrade them to the canonical schema without data loss.
- Legacy helper modules (`database.py` and `repositories/`) remain in place for backward compatibility of standalone Sprint 1 unit tests, but are clearly documented as superseded by `SQLiteStorage`.
